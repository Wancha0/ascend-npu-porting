# 快速训练与资产准备

适用于“尽快打通”“验证训练可行性”等任务。首要结果是完整原模型、真实数据的一次有效参数更新；减少与该结果无关的准备，不削弱模型真实性。

## 先确定最短的实际执行路径

- 用户已指定拓扑且框架已有可用证据时，直接准备该拓扑的真实训练。只对当前未知项做局部诊断，不自动安排单卡、双卡、四卡、八卡阶梯。
- 从实际训练构造入口列出必需权重、数据和缓存。仅用于推理/评测的发布 checkpoint 不阻塞从预训练基座开始的训练；是否必需由源码决定。
- 在所选解释器、源码工作目录中快速确认项目包及入口依赖可导入。需要安装本项目时，可在依赖已准备且构建方式允许的情况下使用 `python -m pip install --no-deps -e .`，确认实际 import 路径；不因依赖声明自动覆盖平台 torch/torch_npu/CANN。
- 在用户允许的可行性范围内选择能容纳完整模型的 batch、worker 数和有限更新步数。记录有效全局 batch；保留原有模型结构、可训练模块、真实输入与精度契约。不要预先实现源码并不支持的内存优化；真实 OOM 后依据证据调整。
- 只运行约定的成功更新数；保存、恢复和推理按用户目标排序。后续目标不会因为训练优先而被取消，也不能作为首步训练的无关前置条件。

## 已有资产优先

先检查用户指定的本机/目标机资产目录及已授权的对象存储，例如 OBS；在相关前缀中找所需资产，找到足够来源信息后停止扩展扫描。不要递归遍历整个桶的日志、历史输出和代码目录。

记录简短的“训练所需项 → 已有位置 → 可复用或缺失”映射。按加载需要确认路径、格式、版本和张量契约，必要项缺失时再从官方源补齐。OBS 的列举、下载和断点续传使用现有客户端、SDK 或独立传输工具；本 skill 不要求特定 OBS 客户端，也不实现存储服务配置。源资产只读，恢复到本轮独立目录，复用已完成的传输。

| 资产检查策略 | 何时采用 | 需要做什么 |
|---|---|---|
| 快速可行性 | 用户强调快速打通且未另行要求完整性审计 | 不额外计算大文件 hash；检查加载必需的存在性、可读性、格式和形状 |
| 用户明确 no-hash | 用户要求跳过哈希 | 不运行资产 SHA/MD5 清单或回读校验；已经保存的历史摘要无需删除，也不能冒称本轮已核验 |
| 完整性核验 | 用户要求完整性/归档验收，或具体传输故障需要此诊断 | 对必要范围核验；不能把每次续接都变成全量扫描 |

no-hash 不等于跳过模型 keys/shapes、有限性、真实参数变化或实际退出状态检查。技能包小型版本清单与训练资产校验是不同工作；不要把包自检当作模型门禁。

## 缓存与独立性

原始权重、真实数据及符合当前输入契约的派生缓存可按授权复用；独立适配考察的是代码编写和诊断，不自动要求重新编码全部数据。检查缓存生成配置、文本/条件布局、精度及样本对应；不匹配或来源不足时再重新生成。若用户明确规定只能使用原始资产，则按该更严格契约执行。

独立测试禁止读取的既有适配代码、补丁和实现答案仍不可用。发现有旧项目目录并不意味着可以阅读其中的代码。资源协调与实现提示分别记录，见 [GLM 交接](glm-handoff.md)。

遇到真实错误后修复最小路径，用新 attempt 重试。已保存产物足以做后验参数对比时先使用它们，不为报告字段或验证器错误重跑昂贵训练。
