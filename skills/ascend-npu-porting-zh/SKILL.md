# 昇腾 NPU 模型适配

把用户指定的模型和任务在目标 NPU 上真正跑通，并留下可复现的代码、启动方法和证据。
所有操作服从用户本次目标、既有授权和资源限制。不要把完整模型实测替换成小模型演示，也不要擅自把可行性测试扩大为收敛训练。

本 skill 面向一般 PyTorch 模型，不绑定 ActionWM、FastWAM、ControlNet 或固定卡数。采用三层组织：**通用执行方法 → 按算子/框架能力选择的兼容策略 → 可选历史案例**。案例里的版本、路径、张量形状和补丁均不是默认配置。接到未见过的模型时，按[陌生模型适配方法](references/model-independent.md)从其实际代码建立契约。

本目录可整体复制给 GLM 或其他编码智能体。正文及操作说明为中文，脚本只依赖 Python 3.9+ 标准库；运行模型仍需要目标环境的 PyTorch/torch_npu。无需 Codex、MCP 或先前聊天记录。宿主不自动发现 skill 时，明确要求它读取本文件的绝对路径即可。`agents/openai.yaml` 只是可选界面元数据。

第一次交给 GLM 时从 [README.md](README.md) 开始：它提供输入模板、模式选择及首次动作。模型适配决策仍以本文件和本次用户要求为准。

## 第一次接手

1. **先查状态，后执行。** 阅读已有 `ledger.md`、当前源码差异和本次进程记录；核对最新日志是否晚于台账。已有训练仍活着就接续监控，不能再次启动同一任务。
2. **确定目标。** 写清推理/训练、全参数或指定可训练模块、真实输入、精度、卡数/节点数、最大更新步数、是否要求保存恢复。用户已明确的选择不重复询问。
3. **追踪实际入口。** 从用户要执行的 launcher 找到导入的代码、配置、依赖和数据生产路径，记录每个仓库的 commit、补丁及工作树状态。只改本次执行路径上的问题。
4. **读取必要材料。** 按下面表格选择；不要每轮重读全部文档或重复工具包自检。同一份复制包首次使用时执行 `python3 scripts/self_check.py`；它只检查工具包，不证明 NPU 或模型通过。
5. **明确资产是否备份。** 远程正式训练或大规模特征提取前，按[产物保存与 OBS 选择](references/artifact-backup.md)列出资产、目标位置和备份频率，让用户选择；已有适用选择直接沿用。本地 checkpoint 不等于 OBS 备份。等待选择时继续独立的代码适配和有界测试，不擅自上传。

## 建立简短的执行契约

用文件记录以下信息；未知项标成未知，不能套用历史环境。

- 源码：仓库/commit、改动文件、补丁或内容清单；launcher → 实际库 → checkpoint/cache 的来源关系。
- 环境：目标 hostname、Python 解释器绝对路径、torch/torch_npu/CANN/驱动、架构、NPU 型号和物理卡列表、主存与 HBM。
- 模型：完整/裁剪/量化权重；冻结与训练模块；音频/视频/条件分支；checkpoint 严格加载及必要转换。
- 数据：真实样本数、缓存生成契约、张量形状/dtype、每卡 batch、重复次数、梯度累积及实际全局 batch。
- 运行：唯一输出目录、命令文件、最大 optimizer 更新数、日志、进程身份、完成判据、是否验收恢复。
- 保存：用户的备份选择、各类资产的本地路径及 OBS 目标、同步频率、校验方式和最近一次备份状态；未选择写待确认，不能默认为不备份。

优先保留平台提供的 torch/torch_npu/CANN 组合。额外依赖放隔离环境；确认 wheel 架构和 Python ABI，并防止安装器替换平台 torch。需要更换组合时查询目标版本的[昇腾官方说明](https://github.com/Ascend/pytorch)，不可把案例版本当成通用推荐。

## 执行顺序按证据选择

通常从入口/环境检查，推进到真实形状算子、完整权重前向、真实 loss/backward/optimizer、保存与恢复。**这是诊断顺序，不是必须逐级重跑的清单。**

用户要求“尽快打通训练”时采用 training-first：准备最小必需资产后直接运行完整原模型的一次真实更新。仅供推理的发布权重、完整推理、恢复及审计报告不作为训练前置条件；用户已要求的后续目标仍保留并排在训练之后。资产校验强度按当前契约选择，用户明确不要 hash 时跳过，不以工具默认值或旧计划覆盖新指令。详情见[快速训练与资产准备](references/fast-training.md)。

- 复用源码、环境和输入契约未变的通过记录。只复查会变化的卡占用、路径、改动文件身份与进程状态。
- 用户指定直接验证某个拓扑（例如单节点 8 卡），且入口、资产和运行时已有证据时，检查目标与资源后直接跑目标拓扑。不要插入与当前未知项无关的卡数阶梯、合成数据或重复通信测试。
- 遇到首个真实因果错误，保存堆栈、退出状态及资源状态，修复最小问题，再用新的 attempt 目录重试该真实任务。需要局部诊断时围绕该错误，不能退回与失败无关的示例。
- 模型无法装入时，依据参数、梯度、优化器、激活和主存预算选择 CPU offload 或已支持的分片策略。多卡本身不会合并每卡 HBM；不要把普通复制式训练称为 FSDP。

## 实现时保持的约束

- 在 Accelerate 等框架判断设备之前加载 torch_npu；设备、autocast、seed、同步及显存统计集中处理。
- 按实际 `tensor.device.type` 路由 CUDA 专属内核；保留 CPU/CUDA 原路径，增加窄范围 NPU 实现，避免全局替换和伪造 CUDA 环境。
- dtype、音频 token、条件行对齐、loss、冻结模块和有效 batch 都是模型语义。不得为“跑通”静默改变；确需调整则说明并重建相关缓存。
- 数据并行必须保证初始训练参数一致、所有 rank 参与同步及更新。自定义 HCCL 平均还必须保证各 rank 参数顺序和梯度存在集合一致。
- 检查真实参数变化，不能仅记录“调用了 optimizer.step”。按实际框架确定更新时点和参数名称；取更新前快照、梯度及计数的方法见[模型验收](references/validation.md)。混合精度跳步不能增加成功更新计数。
- 源码之外的依赖修改必须交付版本、原始哈希、小补丁、应用顺序及回滚方式，不能仅保留远端手工改过的 site-packages。

## 判定与交付

区分以下结论，并写出实际测试范围：

| 结论 | 必要证据 |
|---|---|
| 已准备 | 补丁/命令可交接，尚未在目标运行 |
| 推理已验证 | 指定完整权重执行真实入口，输出内容/形状/有限性通过，运行退出码 0 |
| 真实更新已证实 | 真实数据到 loss、反向、同步、optimizer；有限非零梯度、成功更新计数和真实参数变化 |
| 训练运行验收通过 | 上述更新证据加所有目标 rank 完成、launcher 实测退出 0、资源释放 |
| 保存恢复已验证 | 新进程严格恢复模型/优化器/调度器/计数/RNG/数据进度，再完成有效更新 |
| 效果已验证 | 另有用户指定的收敛或任务指标，单步更新不能代替 |

SSH 退出码不等于训练退出码。丢失的退出码用 `null/unknown`，不得根据文件存在或没有异常推断为 0。

通常交付：适配分支、中文 `NPU_PORTING.md`、环境约束、可重跑命令、源码 revision/差异、按 rank 的原始指标、失败记录和未测项。哈希清单按交付要求提供，不是快速训练的固定前置步骤。仅推送用户授权的仓库/分支；不包含权重、数据、缓存、环境目录、凭证或无关日志。

若还要验证 GLM 的**独立适配能力**，冻结 skill 后从干净源代码另做一轮；把人的实现提示和已适配代码输入记录为介入。开发轮成功不自动等于独立复测成功。下一模型必须重新建立契约，不能继承上一模型的通过结论。
