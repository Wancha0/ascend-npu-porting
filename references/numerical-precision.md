# 模型数值适配与特征缓存

用于新编码器适配、精度切换、缓存与在线输出不一致或任务效果异常。先复用现有证据，再用少量真实样本补当前缺口；不默认全量重提特征、重训或遍历全部算子。

## 先确定比较的是什么

- 记录实际权重 revision、加载键及模型分支，预处理、分辨率、帧数、相机顺序、输出层与 token 布局。缓存的旧通用 metadata 可能不是实际加载参数，应以加载代码、运行契约和真实张量交叉确认。
- 分开记录权重 dtype、计算/autocast dtype、输出/存储 dtype。FP32 权重不代表 FP32 前向；FP32 前向后保存 BF16 仍有量化误差；将已有 BF16 权重或特征转为 FP32 不会找回丢失精度。
- 记录 NPU 型号、torch/torch_npu/CANN、实际算子路径，以及 HF32、融合 attention 等相关开关。相同 API 名称或相同 dtype 不能证明不同设备上实现一致。
- 区分三类证据：相同提取配置能否复现缓存；在线配置能否复现提取输出；两者与明确参考实现的差异。前一项通过不能代替后一项。

## 按证据缺口选择小规模对照

使用同一发布权重、同一预处理后的真实输入、eval 模式；覆盖必要相机和普通/尾 batch。比较前统一输出定义，并保存输入身份、参考设备/精度、配置及原始指标。缩小宽度或层数的组件测试不能证明完整发布模型数值正确。

| 要区分的来源 | 有针对性的比较 |
|---|---|
| 低精度计算累积 | 同一参考设备 FP32 与 BF16；CPU 也出现偏差时，不能把全部误差归因于 NPU |
| 平台算子实现 | 相同精度、相同输入比较参考与 NPU；有异常时才追踪少量层或算子 |
| 保存量化 | 将参考 FP32 输出仅转为缓存 dtype，得到量化基线；与真实缓存误差分开报告 |
| 提取/推理形状 | 同一图在真实提取 batch、在线 batch、必要尾 batch 中比较；相同图像与顺序可比，不改预处理 |
| 优化是否等价 | 优化前后固定输入和精度；局部 reshape/RoPE 等价不代表完整模型与 FP32 或 CUDA 等价 |

BF16 累积误差、平台差异、batch 差异通常不能直接相加。CPU FP32 是明确的数值参考，但不等于已验证官方 CUDA 路径。batch 改变可能选择不同内核或计算路径；独立图像编码出现差异并不自动说明图像之间发生 attention。

记录整体余弦、相对 L2、最大/平均绝对误差；稠密特征必要时检查单 token 分布，避免整体均值掩盖局部偏差。相对 L2 的分母明确为参考范数，近零参考另报绝对误差。不要把 L2 百分比描述成成功率下降百分比，也不为所有模型设置统一通过阈值。

## 激活函数不能一律替换

读取当前模型配置和实际模块：精确 erf GELU、tanh 近似 GELU、SiLU/SwiGLU 的语义不同。

若参考要求精确 GELU，而目标设备 `gelu(approximate='none')` 的实测值更接近 tanh 近似，可针对该模型/设备使用显式 erf 实现，并复验必要输出。若模型原本指定 tanh GELU 或 SiLU，换成 erf 反而改变模型。软件或硬件版本改变后不能沿用旧版算子结论而不核实触发条件。

## 2026-09 实测提醒及边界

以下是特定权重、样本和环境的诊断记录，不是通用误差阈值，也不是各模型的默认适配配置。

- V-JEPA2.1 ViT-G：在 Ascend 910B2、torch/torch_npu 2.6.0 上，256 输入、FP32 权重、BF16 前向的四个真实相机帧对 CPU FP32 相对 L2 约 2.38%～5.06%；其中一帧 CPU BF16 自身也有约 4.98% 偏差。说明低精度累积是重要来源，不能全部归因于 NPU。
- 同次 NPU 实测默认精确 GELU 的值更接近 tanh 近似。FP32 前向使用显式 erf 后，最终保存 BF16 的误差约 0.165%～0.168%；保存前误差更小。原提取 batch 回放缓存逐位相同，但 batch 8 与在线 batch 2 在两个样本上约有 1% 差异。缓存可复现不等于跨 batch 无差异。
- 原版 V-JEPA2 当时已使用 FP32 前向和精确 GELU，本次缓存抽样误差约 0.167%～0.169%，接近存储量化基线。不能由 JEPA2.1 的结果反推 JEPA2 有同等误差。
- SigLIP2 Giant 曾在真实单图上出现 CPU/NPU BF16 对 CPU FP32 约 50%/48% 的相对 L2，后改用 FP32 提取及推理；其原生激活为 tanh GELU。此旧样本只说明模型间精度敏感性不同，不代表所有图像或当前版本的误差。
- 本次 DINOv3 ViT7B 使用 BF16 与 SiLU 门控 MLP，因此不直接适用精确 GELU 的修复。没有完整发布模型的同等级对照时，应标为未测，不能由组件测试或其他模型成功推出它没有数值问题。

## 切换精度与效果判定

现有 action trunk 可以读取新精度编码器输出，但用旧精度缓存训练的策略可能遭遇输入分布变化。先固定策略 checkpoint/EMA、观测、文本、状态和随机性，对比动作输出；需要验证效果时用少量相同任务、种子及初态的配对回合，同时记录同步 latency 和显存。任务效果更好需要任务证据，不能仅凭更小的特征 L2 或更低训练 loss 判断。

未经当前任务授权，不把诊断用精度切换直接应用到正在运行的正式评估。不同精度作为独立配置记录结果，不混合累计成功率或延迟。共享计算资源或暂停进程会污染性能测量；优先隔离资源，确有诊断暂停时保留区间和原始记录，在统计中注明并排除受影响时段。

若采用新的训练/推理精度契约，缓存按该契约重新生成，或在有证据支持的容差内明确复用；重训与否由实验目标和对照结果决定。不要无条件全改 FP32，也不要仅切在线精度便声称训练与推理已经对齐。
