# GPT 与 GLM 执行和交接

GPT、GLM 使用相同的文件与执行契约。宿主需要提供文件读写、Shell、必要的 Git/SSH 或云平台接口；模型名称不决定工具是否可用。不依赖特定聊天平台、MCP 或历史对话。

## 直接执行或离线交接

- 目标可达且操作已授权：检查实际代码/环境后执行。
- 目标不可达但源码可读：交付补丁、环境约束、启动配置与验证命令，标为“已准备”；拿到真实运行记录后再提升结论。
- 只有文本接口：提供可交接方案，不描述为已经修改或运行。

## 少读、少重做

先读 SKILL.md 和当前阶段参考。台账顶部仅保留：最新目标及保存策略、最强已证实结论、活跃 attempt/进程/日志、首个因果错误、下一动作。旧计划移到历史区。

使用 rg 定位实际源码和小型状态文件，避免递归扫描权重、缓存及巨型日志。条件未变的检查直接复用。训练启动前记录任务身份；阶段完成或失败立即更新台账。

断线后先查已有任务和最新结果，不能因新会话而重新训练。宿主支持续接就复用；不支持时通过源码、配置、ledger 和产物回执交接。模型训练是否暂停由用户变更的实际影响决定。

## 最短续接提示

```text
读取 [skill]/SKILL.md；源码：[路径]；台账：[路径]。
最新用户要求：[要求]。
先检查活跃任务和最新结果，再接续下一项工作。
复用已有代码、资产与有效验证，避免重复启动。
```

用户专门要求评估智能体独立适配能力时，才冻结 skill 和干净源码，记录实际模型/宿主以及外部提供的实现帮助；普通协作无需额外独立性审计。
