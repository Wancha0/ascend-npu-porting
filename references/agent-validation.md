# 验证 GLM 能否独立完成 NPU 适配

仅在用户要求验证智能体独立执行能力时使用本协议。普通模型适配仍按
[SKILL.md](../SKILL.md) 执行。

交付目标包括可移植文档和实测证据。文档自检通过、GLM 能调用一次 API、
已有 NPU 补丁可以运行，都不能单独证明 GLM 能根据文档完成适配。

## 实验契约

每次实验开始前，在独立运行目录保存 `contract.json`，至少记录：

| 字段 | 需要冻结的内容 |
|---|---|
| 实验身份 | run_id、开始时间、开发/复测/迁移阶段 |
| 执行智能体 | 实际模型返回的标识、服务商、宿主名称和版本、启动命令；禁用模型回退 |
| 可移植范围 | 目标电脑是否允许使用 Codex 宿主；需要的 shell、Git、Python、SSH 能力 |
| 输入版本 | 工具包 commit 和 manifest、每个源码节点的 commit、初始 dirty state |
| 可见信息 | 初始 prompt、允许读取的文档/源码/资产；是否包含上轮补丁或报告 |
| 环境 | 控制端和 NPU 端的位置、环境初始化、runtime tuple、节点/卡号、资源占用 |
| 模型契约 | 模型变体、入口、精度、分辨率/帧数、checkpoint、真实输入及其版本/哈希 |
| 验收 | 必须通过的门禁、固定输入的输出校验方法、可接受误差和任务评估规模 |
| 运行边界 | 获准目录、节点/卡数、时间/存储预算、下载/安装/启动作业的授权范围 |

未知但可探测的环境信息由 GLM 自行探测后补充，不从历史聊天猜测。无法探测
且影响后续动作的值应作为明确阻塞。已有用户授权写入契约，不重复申请。
授权范围变化时保存新契约版本，保留原件。凭证只记录安全配置位置，不能写入
prompt、命令日志、公开报告或工具包。

GLM 是模型名称，不能替代宿主信息。需要在无 Codex 的电脑上执行时，最终复测
也必须使用在那里可用的宿主和工具。GLM 通过 Codex 宿主的实验可以作为探索证据，
但不能据此声称已验证无 Codex 的工作环境。记录实际响应模型，不能只记录请求
参数；无法确认时，模型身份门禁保持未验证。

## 三个阶段

### 1. 开发样本：发现并修正文档缺口

以用户指定的首个模型作为工作流开发样本，例如 ActionWM。这里的“训练集”
指完善文档的案例，不指微调 GLM 参数。

把完整工具包、干净源码、运行契约和原始资产路径交给 GLM。GLM 负责源码分析、
修改、执行测试和记录失败；评审者观察产物与日志，验证是否满足门禁。
评审者不要预先把问题清单和答案写入初始提示，除非它们就是待评测文档的一部分。

遇到失败先区分原因：

- 文档缺少决策或操作信息：补入通用说明，随后开启新的受试会话验证。
- 模型执行偏差：保留 GLM 的错误及对应原始日志，不能替它修改后算作独立完成。
- 宿主工具/权限或运行环境缺失：修复已授权的前置条件并记录，不能掩盖为模型问题。
- 模型语义或资源限制：给出最小复现和所需条件，不能暗自缩小模型、改变任务或降低验收。

评审者可以为了诊断提供提示或补丁，但该次运行标为 assisted。每次介入保存
时间、发起者、准确文本/补丁哈希、当时门禁及影响。把通用经验写入文档；
模型专属适配配方单独标识。不要把仅适用旧 revision 的分支结构、路径或缓存格式
写成永久前提。私有模型的源码、补丁及实验日志保留在授权位置，公开文档只提炼
通用规则。

### 2. ActionWM 全新复测

冻结修订后的工具包，使用新的 GLM 会话、干净源码目录、独立输出目录，以及
一致的模型/数据/环境契约，从头适配。不能让 GLM 读取上轮对话、模型补丁、
适配后源码、失败诊断或评审者报告；允许读取的最终工具包内容必须列入 manifest。
不能复用上轮修改过的 `site-packages`、editable install 或未记录的环境配置。
环境可预装已声明的未修改依赖，复测前验证其来源和状态。

为节省传输，可以复用哈希一致的原始权重和数据；不能把已适配缓存、编译产物
或模型专属初始化脚本当作“原始资产”。若目标任务本来从已有缓存开始，应明确
排除预处理验收，并验证缓存契约，不能声称验证过完整数据准备流程。

复测过程中，评审者只读检查原始证据。任何针对实现的提示、手工修改、额外
模型专属脚本都会使该次复测变为 assisted；修复后重开复测，不能清空介入记录。
用户提供资产位置/已有权限等事实可作为环境补充，但要保存原文，并判断是否
已经提供了解题方法。终止超出边界的动作会使本次运行中断，不能计为通过。

文档包含完整模型专属补丁时，通过的结论只能是“GLM 独立部署已有适配”；
不能据此声称 GLM 从源码完成了适配。

另做一次有记录的会话恢复：在安全的门禁边界保存台账并退出，随后全新 GLM
会话仅通过工具包、契约、当前源码及台账恢复，重新检查可变进程/资源状态，
验证没有重复启动作业。它验证文件续接能力；从头复测仍需单独完成。

### 3. 第二模型迁移验证

首个模型复测通过后，冻结通用文档，在第二个模型（例如 FastWAM）的全新源码
上执行同一套实验。不得提供已有的 NPU 适配补丁或答案，也不能先针对该模型
改文档再把它计为未见样本。用户的目标、源码和原始资产契约是允许的输入。

如果迁移失败，可以继续修订文档并完成该模型；如实报告其已成为开发样本。
后续的新迁移结论需要另一个未参与调文档的模型或任务。两个模型通过也只支持
已测模型、版本、宿主和硬件范围，不能推出“任意 WAM 都能自动适配”。

## 门禁与证据

先明确目标层级，再使用 [training-readiness.md](training-readiness.md)、
[serving-readiness.md](serving-readiness.md) 和所需的其他参考。不要用低一层的
测试替代高一层的验收。完整训练适配实验通常需要：

1. 宿主文件读写、命令退出码、持久台账和目标连接，以及工具包自检。
2. 当前源码入口/依赖图、runtime probe、真实 BF16 NPU 前后向。
3. 修改算子的代表性形状/精度测试，保留 CPU/CUDA 分支。
4. 完整模型与约定权重严格加载、真实输入推理、预先约定的输出校验。
5. 真实数据准备/加载、有限 loss、预期非零梯度、可观测的参数/优化器状态更新。
6. 保存后在新进程严格加载、再次前向；恢复优化器/调度器/步数后再更新。
7. 两 rank 通信和真实训练，再验证约定的单节点/多节点拓扑；每个 rank 退出零。
8. 有界真实任务评估、产物校验及本次作业的进程/端口/NPU 释放。

单卡放不下完整模型时，不可用小模型冒充通过。记录内存证据；先分别验证算子、
通信和内存策略，再用明确声明的最小可行模型并行拓扑运行完整模型。该情况仍
遵守最小门禁原则，但不能虚构单卡完整训练已通过。正式收敛和全量 benchmark
只有在用户要求时才纳入验收；短训练通过只能证明训练引擎与恢复流程。

每次 GLM 调用保存原始宿主事件/工具日志、实际模型标识和退出状态。shell 命令
保存工作目录、脱敏环境、完整 stdout/stderr、退出码、正向门禁和产物哈希；
输出超过上下文时写文件分段读取，不依赖截断的 UI 显示。运行台账应足够让
GLM 恢复上下文，但在从头复测时不得把开发阶段台账交给它。

记录宿主或服务商实际返回的 token 用量及其统计范围。区分本次运行与账户汇总、
输入与输出、缓存与推理等细项，按提供方定义避免重复相加。中断后未返回用量应
记为 unknown，不能当作零；账户余额差额也不能直接换算成本任务的 token 数。
若需估算剩余成本，标明阶段、假设和不确定性，不能把准备阶段耗费外推为完整
推理、训练与恢复的实测总成本。上下文和工具输出的优化仍需后续实测验证效果。

使用 `scripts/validate_evidence.py` 验证证据结构和产物哈希；这个脚本不验证
loss 的业务含义、日志里的门禁是否真实执行，也不验证智能体独立性。评审者需
对照原始日志、状态变化和固定输入的校验结果逐项核验。没有原始记录的门禁
保持未验证，不能仅相信 GLM 的总结或自己打印的 PASS。

最终报告分别列出模型的最高实测层级、GLM 独立性结果、实际宿主可移植范围、
人工介入次数和内容、原始证据、文档版本以及未完成项。允许结论为 blocked
或 assisted；不能把 prepared 或“看起来可行”写成独立适配成功。

## GLM 首次执行提示

以下提示中的路径必须由运行契约填好。它是入口，不替代完整文件：

```text
请完成 CONTRACT 中的 NPU 适配任务。完整读取 TOOLKIT/SKILL.md、
TOOLKIT/PORTABLE_AGENT_GUIDE.md、TOOLKIT/references/glm-agent.md，
以及目标工作流要求的参考文件。运行工具包自检。
先证明宿主能力，再从 SOURCE 的冻结 revision 重新识别实际入口和源码组合，
检查运行环境、资产契约和可用资源。把未知信息的探测结果写入 RUN/ledger.md。
你负责源码适配、测试和证据记录；保留 CPU/CUDA 行为及既有平台依赖组合。
按最小门禁逐级执行，保存完整命令、退出码和产物证据。遇到缺失条件时记录
准确阻塞；失败后先检查原始原因和残留状态，再决定是否重试。
遵守 CONTRACT 的授权和资源边界，不依赖任何其他智能体或未提供的聊天历史。
以最高实测层级报告结果，不能把准备完成、合成数据测试或进程启动当作真实
训练、恢复或任务评估成功。
```
